# 研究室配属システム

学生の希望順位と研究室ごとの点数（GPA点 + 教員裁量点）から、安定マッチングで
研究室配属を決めるブラウザアプリです。

マッチングには [`hospital-resident-matching`](https://github.com/dfukagaw28/hospital-resident-matching)
の `stableMatch()`（学生側最適の受入保留アルゴリズム）を使います。

**使う → https://dfukagaw28.github.io/ducis-lab-assignment/**
（インストール不要。ファイルはブラウザの外に出ません）

設計は [DESIGN.md](DESIGN.md) を参照してください。

## 動かす

```bash
npm install
npm run dev      # http://localhost:5173
```

`index.html` は `/src/main.ts` を TypeScript のまま読み込むので、Vite 経由でしか
動きません。静的に配信するときはバンドルしてください。

```bash
npm run build    # 型検査 + dist/ にバンドル
npm run preview  # dist/ を配信して確認
npm run typecheck
npm test
```

`dist/` は相対パス（`base: "./"`）で参照するので、GitHub Pages でもサブディレクトリ
でもそのまま置けます。

## 公開する

ビルドしたアプリは GitHub Pages で配信されます。

**https://dfukagaw28.github.io/ducis-lab-assignment/**

計算はすべてブラウザの中で完結するので、公開しても入力ファイルがサーバに送られる
ことはありません。ただしリポジトリを公開にすると `samples/` も公開されます
（匿名の合成データだけが含まれます）。

## 入力ファイル

**3 種類**のファイルをドラッグ＆ドロップします（研究室のファイルは任意で、4 つ目に
なります）。種類はファイル名から推測し、外れていれば画面のプルダウンで直せます。

CSV・Excel (`.xlsx`)・e-class 出力 (`.txt`) を受け付けます。Excel は
`教員裁量点` / `GPA` / `成績` / `研究室` / `希望順位` という名前のシートがあればそれを、
無ければ最初のシートを読みます。

| 種類 | 形式 | 枚数 |
| --- | --- | --- |
| 希望順位 | e-class 出力（`.txt`）、または `学籍番号,氏名,第1希望,第2希望,…` の CSV | 1 |
| GPA | `学生ID,学生氏名,GPA` の Excel（名簿を兼ねる）。CSV も可 | 1 |
| 教員裁量点 | `学生ID,学生氏名,教員氏名,教員裁量点` の Excel（教員ごと）、または `研究室,学籍番号,裁量点` の CSV | 教員ごと、またはまとめて 1 |
| 研究室（任意） | `研究室,研究室名,定員,選択肢ラベル,教員氏名`（`研究室` 以外は任意） | 0 か 1 |

- 見出しは別名を許します（`学籍番号` / `学生番号` / `ID`、`裁量点` / `点数` / `得点` など）
- **定員の列は省けます。**省くと合計がちょうど学生数になるように割り当てます
  （各研究室に「学生数 ÷ 研究室数」の切り捨て、余った席を第 1 希望に挙げた学生が
  多い研究室から 1 つずつ、同数なら抽選）。そう決めたことは警告に出ます。一部の
  研究室だけ空欄なのは書き忘れとみて止めます
- 希望の列は `第N希望` の N の順に読みます。そう名づけられた列が無ければ、学籍番号と
  氏名を除いた残りの列を左から順に希望とみなします
- 文字コードは UTF-8 と Shift_JIS を自動で見分けます（Excel の CSV は多くが後者）
- 書き出す CSV は Excel が文字化けしないよう BOM 付き UTF-8 です

### 研究室のファイルは要りません

研究室の一覧は e-class の選択肢から読み取ります（誰も挙げなかった研究室も含めて
全部そろいます）。定員は自動で決まるので、研究室のファイルは省けます。

「教員裁量点ファイルの**教員氏名**」と「希望順位ファイルの**研究室名**」の対応付けが必要ですが、
e-classの選択肢ラベルが `○○研究室（○○　○○）` のように**括弧の中が教員氏名**
であれば、自動で繋がります。

括弧の中が教員氏名でない場合だけ、研究室 CSV でその対応を書いてください。

```
研究室,研究室名,定員,選択肢ラベル,教員氏名
L01,○○研究室,3,○○研究室（○○　○○）,○○　○○
```

研究室 ID・研究室名・選択肢ラベル・教員氏名・選択肢ラベルの括弧の中のどれからでも
引きます。空白（全角・半角）の入れ方の違いは無視します。突き合わせられないものが
あれば、その名前と入れるべき列を挙げて止まります。

### 教員裁量点の Excel

教員には `学生ID` と `学生氏名` を埋めたテンプレートを配り、`教員氏名` 列
（「教員氏名リスト」シートから選ぶ）と `教員裁量点` 列（60 点満点、0 点も省略せず
`0` と記入）を書いて返してもらいます。

### 名簿の突き合わせ

GPA のファイルと教員ごとの裁量点のファイルは、同じ学生を並べたものです。揃って
いなければ警告します。

- 名簿にいるのに教員の表に無い学生 → その教員の表から行が消えている（その研究室で
  0 点として扱われるので、黙って不利になる前に気づけるように）
- 教員の表にいるのに名簿に無い学生 → 無視します

### e-class のファイルを覗く

読み込みでつまずいたときのための道具です。

```bash
npm run inspect -- data/eclass.txt              # 先頭 3 行ずつ
npm run inspect -- data/eclass.txt --rows 10
npm run inspect -- data/eclass.txt --block 回答  # そのブロックだけ全部
```

ヘッダ・パラメータ・ブロックを列番号つきで並べます（選択肢ラベルは HTML タグを
外したものも併記）。`splitSections` が通らなければ、その理由と先頭 30 行をそのまま
出すので、`src/io/eclass.ts` の定数を直す手がかりになります。実データの中身を端末に
出すので、既定では各ブロックの先頭 3 行だけです。

### 見本

`samples/` に一式あります。

| ファイル | 中身 |
| --- | --- |
| `answer-utf8-sample.txt` | e-class アンケート教材の「詳細データ」を出力したもの（10 人中 9 人が回答、うち 1 人は全項目「未解答」という設定） |
| `GPA.xlsx` | 名簿と GPA（10 人） |
| `教員裁量点_○○先生.xlsx` ほか 3 つ | 記入済みの教員裁量点 |

この 3 つだけで動きます（研究室のファイルは要りません）。

## パラメータ

| パラメータ | 既定 | 意味 |
| --- | --- | --- |
| 抽選シード | 入力データから導く | 総合点が同点のときの抽選に使う。手で指定もできる（下記） |
| GPA 配点 | 40 | 全研究室で共通の持ち点 |
| GPA の満点 | 4.0 | `GPA / 満点 × 配点` で換算する |
| 裁量点 配点 | 60 | 研究室ごとの持ち点 |
| 裁量点の満点 | 60 | |

研究室どうしで裁量点の水準を揃える必要はありません。マッチングが使うのは研究室の
中での順序だけなので、ある研究室が全員に高い点を付けても結果は変わりません。

## 希望順位が不完全なとき

学生が全研究室に順位を付けていない場合（未回答、途中まで、まったく無し）、順位を
付けた研究室をそのままの順で上位に置き、**残りの研究室をランダムな順で下位に足して**
から解きます。乱数は抽選シードから決まるので再現できます。

**希望順位を一度も出していない学生**（e-class の希望調査に回答しなかった学生、全項目未解答の
学生）も配属の対象ですが、**希望を出した学生より後回し**になります。どの研究室も
提出者を未提出者より上に見るので、提出しなかった学生が提出した学生を押しのける
ことはありません。結果として、提出者が収まった後の空きに入ります。

未提出者どうしは総合点で並びます。何人が未提出だったかは警告に出ます。

定員の合計が学生数以上なら未配属は出ません。代わりに、自分で順位を付けていない
研究室に配属された学生が出ることがあり、結果では**希望外**として区別します
（画面の内訳、学生別の「希望外」列、サマリの「希望外に配属」）。希望順位の
内訳には数えません。

## 出力

結果は画面に出て、**Excel 1 冊**（3 シート）か、**CSV 3 枚**としてダウンロードできます。
中身は同じです。

- **学生別** — 学籍番号 / 氏名 / GPA / 抽選番号 / 配属研究室 / 研究室名 / 希望順位 /
  希望外 / 未提出 / 総合点 / 研究室での順位
  （研究室ごとにまとめ、研究室の中は学生 ID 順。未配属は最後）
- **研究室別** — 研究室 / 研究室名 / 定員 / 配属人数 / 第1希望者 / 倍率 / 希望者 /
  合格ライン / 配属順位 / 学籍番号 / 氏名 / 総合点 / 希望順位
  （研究室ごとに、配属された学生を総合点の高い順で）
- **サマリ** — 使ったシードとその決め方、パラメータ、希望順位の内訳、ブロッキングペア数

Excel には数値を数値のまま入れてあるので、そのまま並べ替えや集計ができます。

### 抽選番号

学生別の「抽選」列です。**総合点が同点のときだけ**効きます（1 点でも違えば結果に
影響しません）。**番号は小さいほど優先**で、0 が最も優先、学生数 − 1 が最も不利です。

**シードは入力データから導きます。**人がシードを選べると、「結果を見てから、特定の
学生に有利なシードを選んだのではないか」という疑いが残ります。入力データの関数に
すれば誰も選んでいないので、選び方を疑う余地がありません。公開された入力ファイルから
第三者が同じシードを計算できるので、「このシードを使った」と申告する必要もありません。

学籍番号と研究室 ID を辞書順に整列してから計算するので、ファイルの行順にも、どの順に
落としたかにも依りません。逆に、点数を 1 点でも変えればシードは変わります。つまり
**シードは入力データの指紋を兼ねます** — 保管したファイルで再実行して違うシードが
出たら、データが変わっているということです（32bit なので、検出できるのは取り違えや
壊れの類までで、改竄の証明にはなりません）。

シードを手で指定することもできます（「手で指定する」にチェック）。その場合は
**そのことがサマリに記録される**ので、切り替えたこと自体が結果に残ります。

**全研究室で同じ番号を使います**（single tie-breaking）。研究室ごとに引き直す方式では
ないので、「A 研究室では有利、B 研究室では不利」ということは起きません。学生一人に
つき番号が 1 つなので、「あなたの抽選番号は N 番」と開示でき、監査もできます。

共通の番号は不運を一人に集中させます（番号が大きい学生は同点になったすべての研究室で
負ける）。研究室ごとに引き直せば不運は分散しますが、説明と監査が難しくなります。
総合点は GPA 点と裁量点の和なので完全な同点は稀で、実際にどれだけ効いているかは
[抽選シードによるぶれ](#抽選シードによるぶれ)で測れます。何人も動くようなら、抽選
方式を変えるより点数の刻みを見直す方が説明しやすい配属になります。

### 2 つの順位の列

順位の列が 2 つありますが、別のものです。学生別の **`研究室での順位`** はその研究室が
点を付けた全学生の中での順位、研究室別の **`配属順位`** は配属された学生の中での順位です。

### 合格ライン

希望を出した学生がその研究室に入るのに要した総合点です。安定マッチングの性質から、
この線は「下回った提出者は入れなかった」と同時に「上回った提出者は入れた（か、もっと
上の希望に入った）」も意味します。「なぜ入れなかったのか」への答えになります。

**線が出ない研究室もあります。**定員に空きがあるか、希望を出さなかった学生が入って
いる研究室です。どちらも「希望していれば入れた」ということなので、線がありません。

```
研究室        配属/定員  第1希望(倍率)  希望者  合格ライン
○○研究室      3/3       2人 (0.7倍)    8人     なし   ← 未提出者が入っている
△△研究室      2/2       2人 (1.0倍)    8人     59.7
□□研究室      2/2       1人 (0.5倍)    8人     なし
◇◇研究室      3/3       3人 (1.0倍)    8人     28.4
```

### 希望の集中度

「第 1 希望」はその研究室を第 1 希望に挙げた学生の数と、定員に対する倍率。「希望者」は
どこかに挙げた学生の数です。どちらも希望を出した学生だけを数えます（未提出者は
どこも希望していないので入りません）。

今年の結果を説明するときにも、来年度の定員を決めるときにも使えます。

### 希望順位の内訳

画面では人数・割合の横に帯が付きます。帯の長さは学生数に対する割合なので、
「ほとんどが第 1 希望に入った」がそのまま長さになります。色は明暗どちらの地でも、
色覚特性のある人にも見分けが付くことを検証したものを使っていますが、区分名と人数は
どの行にも文字で出るので、色が見えなくても読めます。

### 安定性の検査

安定マッチングにはブロッキングペア（今の配属より互いを選びたい学生と研究室の組）が
存在しないので、結果画面でそれを検査しています。0 でなければデータか実装を疑って
ください。

## 要確認の学生

結果画面に、目を通しておきたい学生をまとめた表が出ます。全体の表から目で拾わずに
済むようにするためのものです。重い理由の順に並びます。

| 理由 | 意味 |
| --- | --- |
| 未配属 | どこにも入っていない（定員の合計が足りていない） |
| 未提出 | 希望を出さなかったので、余った枠に入った |
| 希望外 | 希望は出したが、挙げた研究室に入れなかった |
| 下位希望 | 第 3 希望以下になった |

```
未提出  1234560005  山田　テスト   □□研究室
未提出  1234560007  鈴木 サンプル  ○○研究室
```

学生別 CSV / Excel には `希望外` と `未提出` の列があるので、表計算側で絞り込むことも
できます。

## 抽選シードによるぶれ

同点は抽選で崩し、順位を付けなかった研究室はランダムに並べます。つまり**シードは
配属を左右します**。どれくらい左右するかを、結果を確定する前に確かめられます。

結果画面の「抽選シードによるぶれ」で試行回数を決めて実行すると、定員は今の値のまま
シードだけを振り直して解き直し、今の結果と比べます。

```
配属先が動かなかった      8 / 10 人
1 回あたり動いた人数      平均 0.4 人
第 1 希望に入れた人数     8 〜 8 人（平均 8.0）

1234560005  80%  □□研究室 80%　○○研究室 20%
1234560007  80%  ○○研究室 80%　□□研究室 20%
```

- ほとんど動かない → 点数で決まっている。抽選は形式的なもの
- 何人も入れ替わる → 同点が多く、抽選が実質的に配属を決めている。点数の付け方
  （配点や裁量点の刻み）を見直す余地があります

分析にも今のシードを使うので、同じ入力・同じシードなら分析結果も同じになります。
